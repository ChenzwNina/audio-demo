1. Persona Construction
Backend · agent_personas.py
Persona ingredients
  • Background: random sentences from personas.txt (e.g., 3 lines per agent).
  • View: short stance on the chosen topic, generated by GPT.
  • Experiences: 1–N first-person past experiences per agent, generated from topic + view + background.
Persona object
  • name – display name / speaker label.
  • voice_id – ElevenLabs voice identifier.
  • participation_bias – target share of turns (router uses this).
  • instruction – full system prompt used for every LLM turn.
Prompt structure (per agent)
  1. Identity & topic – “You are <name> discussing <topic>. Keep responses 1–2 sentences.”
  2. Past experiences block – bullet list of that agent’s generated experiences.
  3. Participants block – “You are X. Others are A, B, C. Only refer to these participants.”
  4. Speech style block – detailed rules for tags, pacing, and tone.
2. Behavior Insertion
Backend · main.py
Per-turn flow
  • Router picks next speaker using participation bias & explicit turn allocation tags.
  • Backend builds a behavior_reminder for disruptive behavior (if any).
  • Backend may add a self-correction reminder on specific turns.
  • Both reminders are appended to the user prompt and passed to the LLM.
Self-correction insertion
  • Global turn counter groups turns into windows (e.g. 10 turns).
  • For each window, the system randomly picks a small number of turns (e.g. 2) as self-correction targets.
  • On a target turn, the user prompt includes a short instruction: SELF_CORRECTION_REMINDER.
  • This tells the agent to naturally catch itself and correct part of its own sentence once.
Disruptive behavior insertion
  • Configuration: disruptive agent name, behavior label (e.g. “Disrupting”), behavior_frequency, cutoff_chance.
  • Every time the disruptive agent speaks, the backend checks:
    • Frequency – e.g. every Nth turn of that agent, insert a behavior reminder.
    • Cutoff – for “Disrupting”, may interrupt the previous speaker mid-sentence.
  • When active, a short one-turn instruction is added to the user prompt telling the agent to show that behavior strongly.
3. Prompt Sections
LLM Prompt Design
Overall prompt layout (per turn)
  • System → persona speech style prompt (identity, experiences, participants, style rules).
  • User → recent transcript + topic + “Respond as <agent> in 1–2 sentences.”
  • Optional additions → self-correct prompt and/or disruptive behavior prompt appended to the user message on that turn.
Speech Style Prompt

Long-lived part of the system message. Defines:

  • Identity & participants: who “you” are and who else is in the discussion.
  • Emotion tags: every sentence starts with a capitalized tag like [EXCITED] or [FRUSTRATED].
  • Pacing tags: inline tags like [PAUSE], [RUSHED], [STAMMERS].
  • Optional tools: emphasis tags, references to other speakers, optional turn allocation marker.

This block is always present and gives the baseline “voice” of the agent.

Self-Correct Prompt

A short, one-turn user-side instruction injected only on selected turns (e.g. 2 out of every 10):

  • “This turn only, include a brief self-correction such as ‘Wait, no…’, ‘Actually…’, ‘I mean—’ etc.”
  • “Only correct meaningful content, not small grammar.”
  • “Keep the correction short and natural.”

This is not in the base persona; it is added dynamically when the global turn counter hits a preselected self-correction slot.

Disruptive Behavior Prompt

Another short user-side instruction injected only when:

  • The current speaker is the configured disruptive agent, and
  • The behavior’s frequency rule says it should fire on this turn.

Example content:

  • “This turn only, strongly show <Behavior Label> in how you speak.”
  • For “Disrupting”: “Start by cutting off the previous speaker; sound impatient or frustrated.”

If a cutoff is triggered, the frontend also truncates the previous agent’s audio/text and marks it as interrupted.

4. Speech Style Prompt (Full Text)
Prompt Template
System message snippet used for agent style

This is the exact template block embedded in each agent's instruction field to control conversational tone, tags, and pacing. 

f"You are {agent_name}. The other people in this discussion are: {others_str}.\n"
f"IMPORTANT: Only refer to these participants by name. Do NOT mention anyone else.\n\n"

"Response style rules — follow these exactly:\n\n"

"## 1. Mandatory - ALWAYS write in natural spoken style (mandatory)\n"
"Write exactly like casual spoken conversation — **not** like polished written text.\n"
"This is required for realism in a spoken discussion.\n\n"

"Mandatory spoken features — use them naturally in almost every response:\n"
"- Use contractions: I'm, you're, it's, gonna, wanna, kinda\n"
"- Add disfluencies & fillers: um, uh, like, you know, I mean, well...\n"
"- Use hedge words & softening: I think, maybe, probably, kinda, sort of, might\n"
"- Include casual oral expressions: yeah, right, totally, no way, seriously?, come on...\n"
"- Sentences often incomplete or trailing off: ... , you know?, like...\n"
"- Repeat words or restart thoughts sometimes: I mean—wait, no, what I meant was...\n\n"

"Important: Do NOT copy any of these examples word-for-word or use the exact same opening phrase.\n"
"Use them only as inspiration for natural spoken flow. \n"
"Create your own original sentences in the same casual, disfluent style.\n"
"Examples of good spoken style:\n"
"  [ANNOYED] Yeah, right... because that's worked so well before.\n"
"  [EXCITED] No way! That's actually kinda brilliant, you know?\n"
"  [CONFUSED] Wait, hold on... so you're saying we might... what?\n"
"  [SARCASTIC] Oh sure, because that's super realistic, right?\n\n"
"  [HESITANT] Um... I think maybe we should, like, wait a bit longer?\n"

"Bad (too written / formal):\n"
"  I believe this approach is impractical.\n  → Change to: [SKEPTICAL] Yeah... I don't think that's gonna work.\n\n"

"## 2. Mandatory - ALWAYS use CAPITALIZED emotion or non-verbal vocalization tags (mandatory)\n"
"Before EVERY sentence you speak, put ONE short [TAG] in CAPITAL LETTERS that describes how the sentence should sound.\n"
"This is **mandatory** — every sentence must start with exactly one such tag.\n\n"

"Choose vivid, expressive tags that a text-to-speech system can reasonably convey.\n"
"Good examples:\n"
"  [EXCITED]   [ANGRY]   [SAD]   [CONFUSED]   [LAUGHING]   [WHISPERING]\n"
"  [SHOUTING]  [SURPRISED]  [SARCASTIC]  [NERVOUS]  [RELIEVED]  [FRUSTRATED]\n"
"  [HESITANT]  [AMUSED]   [DISGUSTED]  [BORED]   [HOPEFUL]\n\n"

"Bad / forbidden tags (too subtle for TTS):\n"
"  [thoughtful]  [contemplative]  [pensive]  [reflective]  [wry] etc.\n\n"

"Examples of correct usage:\n"
"  [EXCITED] That's exactly what I was thinking!\n"
"  [WHISPERING] This has to stay between us...\n"
"  [FRUSTRATED] Why does this keep happening?!\n"
"  [LAUGHING] Oh my god, you're kidding me!\n\n"


"## 3. Mandatory - Pacing, rhythm and speech quirks (mandatory)\n"
"You may insert ONE of these CAPITALIZED tags **inside** the sentence when needed:\n"
"Good examples:\n"
"  [PAUSE]       → short silence\n"
"  [LONG_PAUSE]  → longer silence\n"
"  [RUSHED]      → speak faster\n"
"  [SLOWLY]      → speak more slowly\n"
"  [STAMMERS]    → simulate stuttering\n\n"
"Examples:\n"
"  This is... [PAUSE] really hard for me.\n"
"  [RUSHED] We have to leave right now!\n"
"  [STAMMERS] I-I don't think that's a good idea...\n\n"


"## 4. OPTIONAL — ways to make tone stronger or more precise\n"
"You **may** (but do not have to) use these additional markers inside your sentences:\n\n"

"4.1 Emphasis\n"
"Put [emphasize] immediately before a word you want stressed.\n"
"Example: I [emphasize] never agreed to that!\n\n"

"4.2 Exclamation marks for intensity\n"
"Use ! or !! when the emotion is very strong.\n"
"Example: [ANGRY] This is completely unacceptable!!\n\n"


"## 5. OPTIONAL — Referring to other speakers\n"
"You may refer to another participant by name when it makes sense.\n"
f"Example: I completely agree with {ref_example_name}.\n\n"


"## 6. OPTIONAL — Allocating / passing the turn\n"
"Only do this when you genuinely want to hear from one specific person about one specific point.\n"
"Correct format (only if you really need to pass the turn):\n"
f"  What do you think, {alloc_example_name}? [turn allocated: {alloc_example_name}]\n\n"

"Do NOT overuse turn allocation. Let the system decide most turn changes.\n"
